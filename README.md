# ПОС

Консольное приложение для преподавательской оценки студентов. Написано на C# и .NET 6. Данные хранятся в памяти, поэтому после закрытия программы студенты, критерии и оценки очищаются. Итоги можно выгрузить в CSV.

## Как запустить

Нужен .NET SDK 6. При первой сборке пакеты скачиваются из NuGet.

```powershell
dotnet build Pos.sln
dotnet run --project Pos
```

В меню можно добавить студента и критерии оценивания, выставить, исправить или отменить оценку, посмотреть списки и итоги. Для выбора студента и критерия используются их номера в списке. Дробные числа можно вводить с точкой или запятой.

Для запуска готового примера:

```powershell
dotnet run --project Pos -- --demo
```

В примере добавляются Анна и Иван, а также два критерия: домашка с весом 0,4 и экзамен с весом 0,6. Максимум по каждому — 10 баллов. У Анны оценки 8 и 6, поэтому итог — 6,8. У Ивана только 10 за домашку: если пропуск считать нулём, итог будет 4. Если требовать все оценки, итог пока не выставляется.

В конце примера результаты сохраняются в `results.csv` в текущей папке. В обычном меню путь для экспорта вводится вручную. Если файл уже существует, он перезаписывается.

## Как устроен проект

В [Domain](Pos/Domain) находится модель курса. `Student` хранит идентификатор и имя студента, `Criterion` — название, максимальный балл и вес критерия, `Evaluation` — оценку студента по критерию.

[Course](Pos/Domain/Course.cs) хранит студентов, критерии и оценки. Через него выполняются все изменения. Для одной пары «студент + критерий» хранится одна оценка: повторное выставление заменяет предыдущую. Если новый балл некорректный, старая оценка остаётся.

[FinalScoreService](Pos/Domain/FinalScoreService.cs) рассчитывает итог по текущим оценкам и выбранному правилу. Итог приводится к шкале от 0 до 10:

```text
итог = 10 × сумма((балл / максимум) × вес) / сумма(весов)
```

Веса не обязаны давать в сумме единицу, а максимумы критериев могут различаться. Результат округляется до двух знаков. По умолчанию пропущенная оценка считается нулём. В меню можно выбрать другое правило: не считать итог, пока нет всех оценок. При пустом рубрикаторе итога нет в обоих случаях.

[PosFacade](Pos/Application/PosFacade.cs) связывает действия приложения: получает курс из репозитория, вызывает методы модели, сохраняет изменения и передаёт итоги на экспорт. [InMemoryCourseRepository](Pos/Infrastructure/InMemoryCourseRepository.cs) хранит курс в памяти, а [CsvResultExporter](Pos/Infrastructure/CsvResultExporter.cs) записывает итоги в файл.

[ConsoleMenu](Pos/ConsoleMenu.cs) читает ввод и показывает результаты. В [Program.cs](Pos/Program.cs) настраивается DI-контейнер и запускается меню.

## DDD и архитектура

Используется облегчённая Clean Architecture. Приложение находится в одном проекте Pos. Слои разделены папками:

- **Domain** — модель курса, проверки данных и расчёт итога.
- **Application** — сценарии приложения и интерфейсы хранения и экспорта.
- **Infrastructure** — реализации хранения в памяти и экспорта CSV.
- **Program.cs и ConsoleMenu.cs** — меню и настройка DI в корне проекта.

Направление зависимостей в коде: `ConsoleMenu → Application → Domain`, `Infrastructure → Application / Domain`. В Program.cs реализации подключаются через DI. Домен не знает про файлы и консоль. Слои находятся в одной сборке: их разделение поддерживается кодом и пространствами имён, а не ссылками между отдельными проектами.

Элементы DDD в коде:

- **Единый язык:** студент — `Student`, критерий — `Criterion`, оценка — `Evaluation`, курс — `Course`. Эти названия используются и в модели, и в сценариях приложения.
- **Entity:** студент и критерий имеют собственные идентификаторы. Два студента с одинаковым именем остаются разными студентами. Оценка определяется парой идентификаторов студента и критерия.
- **Value Object:** [Score](Pos/Domain/Score.cs) хранит неизменяемый балл и сравнивается по значению. Отдельного идентификатора у него нет.
- **Агрегат:** `Course` объединяет студентов, рубрикатор и оценки. Списки доступны снаружи только для чтения. Для одного небольшого курса этого достаточно.
- **Инварианты:** пустые имена и названия, неположительные максимумы и веса, оценки вне диапазона критерия не допускаются. Нельзя выставить оценку неизвестному студенту или по критерию, которого нет в рубрикаторе. Проверки находятся в модели, а не только в меню.
- **Repository:** [ICourseRepository](Pos/Application/ICourseRepository.cs) описывает получение и сохранение курса. Реализация находится в инфраструктуре.
- **Domain Service:** `FinalScoreService` рассчитывает итог, т.к. для этого нужны оценки студента и весь рубрикатор.

Приложение рассчитано на один курс. Редактирование и удаление студентов и критериев не добавлялись, т.к. в задании они оставлены по необходимости. Исправление и отмена оценок реализованы.

## Паттерны GoF

- **Фабрика, порождающий:** [EvaluationFactory](Pos/Domain/EvaluationFactory.cs) создаёт оценку после проверки студента, критерия и балла. Она используется и при первом выставлении, и при исправлении, поэтому проверки не дублируются.
- **Фасад, структурный:** `PosFacade` даёт консоли готовые действия. Меню не приходится самостоятельно обращаться к репозиторию, рассчитывать итог и вызывать экспорт.
- **Стратегия, поведенческий:** [IFinalScoreStrategy](Pos/Domain/IFinalScoreStrategy.cs) позволяет менять правило расчёта. `WeightedScoreStrategy` считает пропуски нулями, а `CompleteScoreStrategy` требует оценки по всем критериям. Правило выбирается в меню.

Для добавления нового правила расчёта нужно реализовать IFinalScoreStrategy, зарегистрировать его в DI и добавить выбор в меню.

## Тесты

Запуск тестов:

```powershell
dotnet test Pos.sln
```

В [DomainTests](Pos.Tests/DomainTests.cs) проверяются основные правила модели:

- допустимые границы балла и отказ при неизвестном студенте или критерии;
- исправление и отмена оценки, сохранение старой оценки при ошибке;
- ограничения имён, максимумов и весов;
- расчёт с разными максимумами и весами, округление и обе политики пропусков.

[ApplicationTests](Pos.Tests/ApplicationTests.cs) проверяет сценарии через фасад, сохранение курса и экспорт CSV, включая кавычки и переносы строк в именах. [ConsoleMenuTests](Pos.Tests/ConsoleMenuTests.cs) проверяет добавление студента и критерия, выставление оценки и вывод итога через меню.

## Использование ИИ

ИИ использовался для помощи в проектировании архитектуры, также он помогал с написанием тестов и консольного меню, проверкой работы программы и написанием документации.
